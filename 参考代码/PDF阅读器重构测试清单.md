# PDF 阅读器重构测试清单

> 被测改动：PDF 阅读器从手写 pdfjs-dist core 渲染迁移到官方 `pdfjs-dist/web/pdf_viewer` 的 `PDFViewer`（页面绘制/缓存/预渲染/文本层/缩放交给 pdf.js），自定义能力（目录、续读、划词、标注、翻译、截图）保留并通过叠加层实现。
>
> 测试目标：确认迁移后阅读体验不回退、Zotero 特有功能仍可用、并且 pdf.js 官方样式与宿主界面互不污染。

## 1. 前置条件

### 1.1 环境

- [ ] Zotero 桌面端已启动，本地 API 已开启（插件读取文献/附件依赖它）。
- [ ] DSH 已加载本插件，且使用的是本次构建产物（`pnpm build && pnpm build:client` 之后）。
- [ ] 需要测试「写入标注 / 修改标注 / 删除标注」时，插件设置里的写权限已开启。
- [ ] 需要测试「翻译 / 截图加入对话」时，当前有可用会话（按钮能把内容送进对话）。
- [ ] 建议打开开发者工具（Console + Network），全程留意未捕获异常。

若使用 `dsh web` 在本机浏览器测试：

```bash
# 项目根目录
pnpm build
pnpm build:client

# 首次需要把插件装进 web profile；已装过可跳过
dsh plugin --profile web add ./

# 启动浏览器 UI（端口可换成任意空闲端口）
dsh web --port 8090 --no-open
```

然后访问 `http://127.0.0.1:8090`。若需要登录，使用测试账号或由用户协助登录。

> 若 Zotero 未运行：A/B/C/F/L 等纯前端项仍可测；涉及文献、标注、翻译落库的项标记为 **BLOCKED**，不要直接判失败。

### 1.2 测试文献（PDF 样本矩阵）

请在 Zotero 中准备（或指定附件 key）以下样本。没有的样本可标 **N/A**，但至少应覆盖前 6 类。

| 编号 | 样本类型 | 用途 |
|---|---|---|
| S1 | 普通文字型 PDF，20–50 页，带 PDF 书签和内部链接 | 基础渲染、目录、链接 |
| S2 | 扫描版 PDF（整页图片、无文本层），其中 1–2 页旋转 90° | 旋转页、无文本层选择 |
| S3 | 页面尺寸混排（A4 + 大幅面折页/横向页） | 页面居中、截图、标注几何 |
| S4 | 中文/CJK PDF（含嵌入字体或依赖 cmap 的字体） | cmaps 资源、文字显示 |
| S5 | 大型 PDF（≥300 页） | 性能、懒渲染、跳页 |
| S6 | 已有多类型标注的 PDF（高亮/划线/笔记/手写/截图/文本各至少一条） | 标注叠加层 |
| S7 | 印刷页码为罗马数字或非 1 起编的 PDF（如前言 i–xiv） | 页码输入、截图水印页标 |
| S8 | 加密 PDF（打开需密码） | 异常路径 |
| S9 | 损坏 PDF / 0 字节 PDF | 错误提示 |
| S10 | 含表单域或链接注释的 PDF | annotationLayer 交互 |

建议同时准备一篇「非 PDF 附件」（网页快照或笔记），用于验证渲染器切换。

## 3. 详细测试项

### A. 构建、资源与全局影响

- [ ] **A-01（P0）构建成功**
  - 步骤：执行 `pnpm typecheck:client && pnpm build && pnpm build:client`。
  - 预期：全部命令退出码为 0；`client/pdfjs/pdf_viewer.css` 与 `client/pdfjs/images/` 存在。

- [ ] **A-02（P0）静态资源可访问**
  - 步骤：打开 Network，过滤 `pdf_viewer.css`、`pdf.worker.min.mjs`、`images/`。
  - 预期：`GET /dsh-zotero/static/pdf_viewer.css` 返回 200、`text/css`；worker 返回 200；`images/loading-icon.gif` 或 `loading.svg` 返回 200（不是 404、不是 `application/octet-stream`）。

- [ ] **A-03（P0）样式只注入一次**
  - 步骤：打开文档 A，关闭再打开，切换文档。
  - 预期：页面中 `style[data-dsh-zotero-pdf-viewer]` 始终只有 1 个；内容以 `@scope (.dsh-zotero-pdf-scroll)` 开头。

- [ ] **A-04（P0）pdf.js 官方样式生效且被作用域限制**
  - 步骤：打开任意 PDF，检查页面 DOM 与样式。
  - 预期：`.pdfViewer > .page[data-page-number]` 存在且页面宽度正常；`.textLayer` 为绝对定位、文字透明；页面白底、有阴影、页间有间距；不会出现整页文本裸露在页面上。

- [ ] **A-05（P0）Console 无异常**
  - 步骤：打开、滚动、缩放、划词、标注、截图各一次，观察 Console。
  - 预期：没有 `The container must be absolutely positioned`、`getOrInsertComputed is not a function`、React portal/`removeChild` 相关报错，也没有未捕获 Promise rejection。允许 pdf.js 的字体/语言资源 warning，但需记录。

- [ ] **A-06（P1）样式未污染宿主界面**
  - 步骤：打开 DSH 的设置/确认框/命令面板等任意弹窗或对话框，对比改动前的外观。
  - 预期：弹窗、按钮、输入框、菜单的外观与布局无变化；不会出现 pdf.js 的深色遮罩、异常边框或字体。

- [ ] **A-07（P1）Worker 正常工作**
  - 步骤：打开 S5（≥300 页）。
  - 预期：页面能逐步渲染；Network 中 worker 脚本 200；Console 无 `Setting up fake worker` 以外的异常。

- [ ] **A-08（P2）重复挂载安全**
  - 步骤：在 React StrictMode 下（若可）反复打开/关闭阅读器面板 5 次。
  - 预期：页面不重复叠层、不出现两份 `.pdfViewer`、页码与滚动位置正常。

### B. 加载与基础渲染

- [ ] **B-01（P0）正常打开**
  - 步骤：打开 S1。

- [ ] **B-04（P1）页面布局**
  - 步骤：打开 S3（混排尺寸）。
  - 预期：每页按自身尺寸显示、水平居中；宽页允许横向滚动；页间距一致；背景为浅灰，不出现黑底。

- [ ] **B-08（P1）旋转页与无文本层页**

### C. 缩放

- [ ] **C-01（P1）初始适应宽度**
  - 步骤：打开文档，不点缩放。
  - 预期：页面宽度适配阅读区（左右各留约 20px），无横向滚动条。

- [ ] **C-02（P0）放大/缩小按钮**
  - 步骤：点击工具栏「放大」「缩小」。
  - 预期：每次按预设步进变化（50/67/80/100/125/150/200/300%）；页面与文本层同步缩放。

- [ ] **C-03（P1）缩放上下限**
  - 步骤：连续点击放大 15 次；再连续点击缩小 20 次。
  - 预期：停在 300% 与 50%，不继续变化、不抖动、不出现负尺寸。

- [ ] **C-04（P0）Ctrl+滚轮锚点**
  - 步骤：把鼠标放在某段文字上，按住 Ctrl 向上/向下滚轮。
  - 预期：该段文字在屏幕上大致保持原位（误差应肉眼不可见）；不会跳到页首或别处；连续缩放不累积漂移。

- [ ] **C-05（P1）高倍缩放清晰度**
  - 步骤：放大到 200%/300%，观察文字边缘。
  - 预期：短暂模糊后重绘为清晰字形；不会一直停留在低分辨率拉伸状态。

- [ ] **C-06（P1）缩放过程不闪白**
  - 步骤：快速连续放大/缩小。
  - 预期：页面内容始终可见（旧画面拉伸过渡），不出现整页白闪或黑闪。

- [ ] **C-07（P1）横向溢出**
  - 步骤：放大到页面宽于视口。
  - 预期：出现横向滚动条；页面左对齐（不居中到不可达位置）；可以滚到右边缘。

- [ ] **C-08（P0）缩放后标注对齐**
  - 步骤：打开 S6，缩放到 50%、100%、200%、300%。
  - 预期：高亮/划线矩形始终贴合对应文字，偏差不超过约 2px；不会出现整体偏移一页或只偏移某几页。

- [ ] **C-09（P1）缩放后选区与浮条**
  - 步骤：缩放后划词。
  - 预期：选区高亮位置正确；浮条出现在选区附近且不被页面遮挡；操作按钮可点击。

- [ ] **C-10（P1）容器尺寸变化**
  - 步骤：拖动 DSH 侧栏改变阅读区宽度；缩放窗口；切换侧边栏展开/收起。
  - 预期：适应宽度模式下页面自动重排且保持阅读位置；不会突然放大到 300% 或缩成一条。

## 5. 已知可接受差异（不是缺陷，除非产品另有要求）

1. **100% 缩放的含义变化**：现在 100% 是 pdf.js 标准（96dpi 实际尺寸），同一文档在相同可视宽度下显示的百分比数值会比旧实现更大。属于预期变化。
2. **没有独立「适应宽度」按钮**：初次打开与容器尺寸变化时自动适应宽度；缩放后保持用户比例。
3. **高倍缩放短暂模糊**：pdf.js 先用 CSS 拉伸旧画面再重绘，属正常过渡；不应长期模糊。
4. **远处页面标注延迟出现**：页面首次渲染后才出现叠加层，通常不超过一帧到数百毫秒。
5. **截图不包含用户标注**：当前截图走页面 canvas，是原始版面；若产品要求包含高亮，需单独立项。
6. **pdf.js 语言/图标资源 warning**：如缺少某些 UI 本地化资源，允许出现 warning，但不应影响阅读。
