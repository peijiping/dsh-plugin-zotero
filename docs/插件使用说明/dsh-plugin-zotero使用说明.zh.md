# dsh-plugin-zotero 使用说明

> 设计依据见 [Zotero-DSH插件开发与设计方案.md](../../.trae/documents/Zotero-DSH插件开发与设计方案.md)。

## 0. 这个插件做什么

分两半，职责不重叠：

| 半边 | 能力 | 通道 |
|---|---|---|
| **人侧面板** | 浏览 Zotero 文献库（分类树 / 条目详情 / PDF 全文），把引用写进会话草稿；开启写权限后还能就地改标注与笔记 | 插件在 DSH 宿主 web server 上自注册的 `/dsh-zotero/api/*` 路由 |
| **模型侧** | 检索、精读、按需操作文库 | 桥接本机 Zotero 集成 MCP（`http://127.0.0.1:23120/mcp`），工具名 `mcp__zotero__*`；标注与笔记另用插件自带的 `zotero_*` 工具 |

两条通道互不依赖：MCP 没起，面板照常用；Zotero 没开，模型工具自然也不可用。

**面板不碰分类结构**——没有新建/改名/删除分类的按钮，整理分类是模型的活。标注与笔记的写则放在面板里（划选即高亮、就地改评论），但要「Zotero 写权限」开关打开才出现，默认关着。

## 1. 安装

### 前置

1. Zotero 桌面版已运行，且已开启本地 API（见 §2）。
2. 本机已运行 Zotero 集成 MCP 服务（监听 23120）。缺这个不影响面板，只是模型侧没工具。
3. 主包已构建出两类产物：

```sh
cd /Users/peijiping/Documents/Codes/TS/dsh-plugin-zotero
pnpm install
pnpm build          # tsc：src/ -> lib/（Host 半边）
pnpm build:client   # tsdown：src/client/ -> client/client.js（Client 半边）
```

### 装进 profile

本地路径 link 的完整操作见 [方案一：本地路径安装](../插件发布/方案一本地路径安装.zh.md)，核心三步：

```sh
dsh plugin --profile demo add ./
dsh --profile demo --dump-config   # 应能看到 dsh-plugin-zotero 与 mcp-zotero 两行
dsh --profile demo
```

### 日常迭代

| 改了什么 | 要做什么 |
|---|---|
| `src/`（Host 半边） | `pnpm build` → 重启 dsh |
| `src/client/`（Client 半边） | `pnpm build:client` → 重启 dsh → 浏览器重新打开页面 |
| `cordis.patch.yml` | 重启 dsh |

客户端 bundle **没有热更新**：改完必须重启 dsh 并重新加载页面，否则浏览器拿到的还是上一次构建的字节。

## 2. 开启 Zotero 本地 API

Zotero → 设置（Preferences）→ 高级（Advanced）→ 勾选 **「允许本机其他应用与 Zotero 通信」**。

- 默认端口 `23119`，只监听回环地址。
- 验证：

```sh
curl http://127.0.0.1:23119/api/          # 期望输出：Zotero is running
curl -i http://127.0.0.1:23119/api/users/0/collections | head -1
```

- 未勾选时读端点返回 **403**，面板会显示「Zotero 未连接」并提示启用步骤。
- 注意：裸 `GET /api/users/0` **不支持**（返回 `No endpoint found`），要带子资源路径。

## 3. 面板入口

1. DSH web 界面右上角 → **打开右侧边栏**。
2. 右侧栏选中 **「Zotero 文献库」**。

面板布局：

- 顶部：文库名（如「我的文库」）+ 两个状态点（「Zotero 已连接」/「模型工具可用」）+ **刷新**按钮。
- 左栏（默认 260px）：搜索框 + 分类树；输入关键词后左栏切换为搜索结果。左栏与右栏之间的分隔条**可以用鼠标拖动**调整宽度（左栏最小 180px，右栏至少留 220px），拖动结果会记住，跨会话与重启都保持。
- 右栏：条目列表（分类概要 + 整目录 bib 预览）。每条占两行：第一行**标题**独占，第二行是小字灰色的「**类型 + 年份 + 作者**」；行与行之间用一条浅色细线分隔。单击选中（`Ctrl` / `Cmd` 多选），**双击**打开独立 tab；右键单行可直接「添加条目引用」。
- 右栏标题行最右侧是**排序按钮**：点一下按标题正序（`A→Z`，图标箭头朝上并变蓝），再点切倒序（`Z→A`），第三下恢复 Zotero 原始顺序。排序交给 Zotero 本地 API（`sort=title&direction=`），所以**翻页、搜索、标签筛选、切分类都保持同一顺序**，不是只排当前这一页。状态存浏览器 `localStorage`（键 `dsh-plugin-zotero.itemSort`），全局生效，跨会话与重启都保持。注意中文标题按字符编码排序（Zotero 本地 API 的排序规则），不是拼音顺序。
- 文档页：PDF / 网页快照 / 文本占满整版面，左上角 **`i`** 按钮打开「文献信息」浮层。

浮层里是六块可折叠内容：**文献信息 / 摘要 / 标注 / 笔记 / 附件 / 参考文献（APA）**。点标题行展开或收起，标题行右侧的数字是该项数量；写权限打开时「笔记」标题行右侧还有新建用的 `+`。点浮层外（包括直接点网页快照正文）或按 `Esc` 关闭；再点一次左上角的 `i` 也收起来。

各区块的**开合状态全局记一份**，不按文献分开——换文献、换会话看到的是同一份，关掉浮层再打开也不复位。状态存在浏览器 `localStorage`（键 `dsh-plugin-zotero.info-sections.v1`），跨会话与重启都保持；首次使用的默认是文献信息 / 摘要 / 标注 / 附件展开，笔记 / 参考文献收起。想回到默认就把这个键删掉。

### 笔记区块

浮层里的「笔记」区块（该条目的子笔记，Zotero 里在条目下写的那些笔记）。每条笔记默认折叠成一行标题（正文首段的纯文本摘要），**点标题展开**看正文：

- 正文按 Zotero 原样渲染：段落、引用块、标注高亮（黄底）、引用文献都保留。
- 笔记里的**图片是外链**（如知乎图床），能直接看到；离线或图床失效时显示空白。
- 行尾 **「引用」**（hover 提示「引用到会话」）把该条笔记写进会话草稿：正文会转成纯文本（段落 / 列表保留分行，标签与 HTML 实体剥掉），并附所属条目、更新日期与笔记 key。
- 打开的条目本身就是一条笔记（独立笔记）时，笔记区块显示的就是它自己。
- 写权限打开后，**新建**入口是「笔记」标题行右侧的 **`+`**（再点一次变 `×` 收起），不再单占一行；就地新建 / 编辑 / 删除都在每行右侧。
- **所有笔记都能编辑**（编辑框里是 Zotero 存的那份原始 HTML，改完原样写回）。含引文 / 标注锚点的笔记只在编辑框下方多一句橙色提醒：改文字没事，别动 `data-citation` / `data-annotation` 这些属性。

已知限制：本地 API **搜不到笔记正文**（笔记不进全文索引），所以左栏搜索框按关键词检索时，命中的只是条目的标题 / 摘要，不是笔记内容。

### 标注区块

浮层里的「标注」区块汇总 PDF 上的**高亮**与**划线**（Zotero 里两者可互相转换，这里按当前实际类型显示；note / 文本 / 图片 / 墨迹等其它标注不展示）：

- 每行显示颜色、页码、类型、原文与**评论**；评论保留 Zotero 的加粗 / 斜体 / 上下标与换行。
- 顶部可按**类型**（全部 / 高亮 / 划线）和**颜色**筛选，两者同时生效，正文内联同步只标出筛选后的标注；色块形态区分类型——高亮是实心块，划线是一条横线。
- **正文内联**：全文块里高亮画成半透明底色、划线画成彩色下划线，压在同一段文字上也能同时保留；点列表里的原文 → 正文滚动到该处并短暂闪蓝框。
- **引用**（hover 提示「引用到会话」）把该条标注写进会话草稿，含原文、类型、页码、评论与标注 key。
- **阅读页卡片**：点正文里的高亮 / 划线弹出的卡片就是这一条的快捷操作台，不用回列表——色块点一下换颜色、按钮一键「转换为下划线 / 转换为高亮」、当场「添加评论 / 改评论」、底部「删除」（按两次确认，硬删不进 Zotero 回收站）。页码与标签仍在下面的「标注」列表里改。**PDF 与网页快照共用同一个卡片组件**，能力一致；点卡片外或按 `Esc` 收起，两种条目也一样。
- 定位靠把标注原文匹配回全文。全文被 `fulltextMaxBytes` 截断、标注属于别的 PDF 附件、或原文过短且多处重复时无法唯一定位：这类行置灰并说明原因，但**仍可插入**。

### 网页快照区块

网页类型的条目（`webpage`）如果抓取时保存了网页快照，正文**直接渲染成网页本身**，不再是抽出来的纯文本：排版、图片、字体、侧栏都还原，与 Zotero 阅读器里看到的一致。

- **不需要装浏览器插件**。快照在抓取时就已经存进 Zotero 了（`~/Zotero/storage/<附件 key>/*.html`，SingleFile 打成的单文件，图片与字体全内联）。插件只是把这份本地文件喂给一个沙箱 iframe。
- **高亮与划线按 Zotero 原色叠加在网页上**，点「标注」列表里的原文 → 网页滚动到该处并闪一次蓝框；**点正文里的高亮／划线会弹出与 PDF 完全一样的编辑卡片**（换色、一键转高亮／划线、添加或改评论、删除，需打开写权限），卡片跟着**点击位置**出现——两处 UI 是同一个组件，所以能力不会有差。
- **可以在网页上划选新建高亮**（需打开写权限）：选中文字 → 浮条出现在选区上方 → 点色块。写进去的是 Zotero 原生的网页标注（`CssSelector` + 文本偏移），回到 Zotero 里打开同一份快照，能在同样的位置看到它。
- **限制**：
  - 快照必须**自包含**。Zotero 新版抓取的单文件快照都满足；早期「Web Page, Complete」式的「HTML + 资源目录」在沙箱里加载不了外部资源，可能缺图。
  - 快照里的脚本在**沙箱**中运行：读不到本机任何数据，也不能访问本插件的接口；外链点击交给系统浏览器打开，不会把快照页面本身导航走。
  - 高亮依赖 DOM 结构。若页面脚本改写了 DOM 导致选择器失效，会退化成「按原文文本搜索」；仍找不到的那几条在列表里置灰，页面底部提示「有 N 条标注未能在网页上定位」。
  - 页面顶部出现「**快照脚本是旧版本**」提示时：iframe 里跑的是 Host 缓存的旧桥接脚本，编辑卡片只能居中显示。重启一次 DSH 即可（之后 Host 每次请求都重读 `client/snapshot/runtime.js`，改脚本只需刷新页面）。
- **没有保存快照时**：正文位置显示一条提示 + **「打开原网页」**按钮（不尝试在线嵌入——绝大多数站点禁止被 iframe 嵌入），下面仍会接上 Zotero 索引的全文文本。

### 文档目录

左上角、「文献信息」按钮的左边有一个**目录按钮**（三行列表图标）。点开是 PDF 自带书签（大纲）的层级列表，点任意一条即跳到对应页，跳完自动收起。

- 数据来自 **PDF 文件里的书签本身就有的那棵大纲树**（`getOutline()`）。Zotero 本地 API 与集成 MCP 都**不提供**目录数据——都查过，没有对应端点或工具，所以目录是插件自己从 PDF 里解析的。
- 层级按缩进展示，最多 8 层、800 条（个别 PDF 的书签几千条，再多也翻不过来）。
- 没有书签的 PDF 显示「这篇 PDF 没有目录」。中文期刊与知网下载的不少 PDF 就没有书签——这时目录按钮照样在，只是里面是空的。
- 书签若只指向外链、或目标页解析不出来，那一条置灰不可点。
- 只有**有页码的文档**才出现这个按钮（PDF）；网页快照与纯文本没有页码，不显示。将来若加了别的分页渲染器，只要它自己解析出目录并上报，面板不用改。

### 页码跳转与续读

工具条中间的页码（形如 `12 / 90`）**可以直接点、直接改**：

- 点一下 → 整段选中 → 输入页码 → 回车（或点别处）即跳转；`Esc` 放弃。
- 超出范围按 `1..页数` 夹住，输 999 就是翻到最后一页，不报错。

**续读**：PDF 打开时自动跳回上次在本插件里读到的那一页，左下角提示「已回到上次读到的第 N 页」。

- 进度**只记在本插件自己的存储里**：`<DSH 数据目录>/storages/dsh-plugin-zotero/read-positions.json`，按附件 key 记 0 基页号，最多留 500 篇（超出按最近阅读淘汰）。
- **不与 Zotero 同步**，也不读 Zotero 的任何文件。原因有两条：
  - Zotero 的位置在它的数据目录里（`storage/<附件 key>/.zotero-reader-state`），而那个目录可能是 macOS / Windows 的默认位置，也可能被用户改到任意路径——插件拿不到可靠路径，读了也是时灵时不灵；
  - 语义上本就不该混：你完全可能在面板里读、在 Zotero 里读，两边各记各的才不会「我明明在这读到 20 页，它却跳回 Zotero 记的第 3 页」。
- 打开后**没翻页就关掉**不会写任何记录；翻页（含用页码跳转）后约 0.8 秒防抖落盘，关面板时立即补写一次。
- 只做 PDF；网页快照与纯文本没有页码概念。

分类树是 Zotero 那样的层级结构：根节点「我的文库」默认展开；行首三角箭头只管开合，**点行体**则选中该分类（若还折叠着会顺带展开）；分类行右侧显示条目数，展开后子分类与条目各自缩进一层。

**选中的分类与展开状态会记住**：刷新页面或重开面板后直接回到上次选中的目录，右栏同步重拉该目录的条目（与左栏宽度、排序一样存本机）。三条配套规则：选中的分类在 Zotero 里被删掉时退回「我的文库」；被挪到别的父级下时自动展开到它，不会藏在折叠的父级里；「我的文库」根节点在恢复时恒为展开，否则选中项没有落点。

「我的文库」下除真实分类外，还挂了三个与 Zotero 一致的**虚拟分类**：我的出版物（走 `/publications/items`）、未分类条目（本地 API 无专用端点，由 `/items/top` 过滤掉已归类的条目推导）、回收站（走 `/items/trash`）。它们的条目数只有展开（拉取过）后才显示；虚拟分类不提供整目录 bib，右栏只显示名称与「添加整目录引用」。Zotero 的「最近阅读」与「重复条目」在本地 API 里没有对应端点（`/recents`、`/items/duplicates` 等均 404），故未在树中提供。

分类树是**按需拉取**的：根节点展开**不再平铺全库条目**——这些条目本就挂在各分类下，平铺会造成重复显示；只有展开某个分类 / 虚拟分类时才去取它下面的条目（上限 200 条）。

> 状态点「模型工具可用」只是对 23120 做端口探活，**不代表当前会话真的挂上了 `mcp__zotero__*` 工具**。真正的工具列表由模型侧会话决定。

面板正文会被**每个会话各挂一份**：分类树、搜索词、选中的条目放在模块级单例里，所以各会话看到的是同一块面板；但右侧栏的展开状态与标签页是**按会话**存的，所以新建或切换会话后需要**重新打开一次**面板。

## 4. 五种引用方式

| 方式 | 入口 | 写进草稿的文本 |
|---|---|---|
| **单条目引用** | 详情区标题右侧 **「添加条目引用」** 按钮；或条目行**右键**菜单 → 「添加条目引用」 | `【Zotero 条目｜<itemKey>】标题` + 作者 / 年份 / 出处 / DOI / 链接 / 标签 / 摘要 |
| **摘录** | 全文块内**鼠标拖选**文字 → 浮出 **「添加摘录」** 气泡 | `【Zotero 摘录｜<条目标题>｜<itemKey>】` + `"<原文>"` |
| **单条标注** | 「标注」tab 每行的 **「引用」** 按钮 | `【Zotero 摘录｜<条目标题>｜<itemKey>】` + `"<标注原文>"`，再附 `类型：高亮/划线`、`页码：N`、`批注：<评论>`（有评论时）、`标注：<annotationKey>` |
| **单条笔记** | 「笔记」tab 每行右侧的 **「引用」** 按钮 | `【Zotero 笔记｜<条目标题>｜<itemKey>】` + 笔记正文纯文本，再附 `更新：YYYY-MM-DD`、`笔记：<noteKey>` |
| **整目录引用** | 分类行**右键**菜单 → 「添加整目录引用」 | `【Zotero 目录｜<分类名>｜<collectionKey>】共 N 条` + 每行 `- 标题（作者, 年）` |

五条行为约定：

1. **只写进草稿，不自动发送，不抢焦点**。插完你还能继续改。
2. 五种文本都带 `itemKey` / `collectionKey`——插完可以直接让模型用 `mcp__zotero__*` 接着操作同一批文献（例如「把上面这些条目加进 XXX 分类」）。
3. 摘录**保留原始措辞**，不做改写。超过 50 条的目录只列前 50 条并注明，完整清单提示模型用 `mcp__zotero__get_collection_items` 取。
4. 标注的原文会顺手清掉 PDF 抽取插进汉字之间的空格；评论里的加粗 / 斜体等字面量标签会被剥成纯文本。
5. 笔记正文按 HTML 结构转纯文本：段落 / 引用块 / 列表各自分行，列表项加 `- `，标签与 HTML 实体（`&amp;` 等）解码成字符，图片等无文字内容不占位。

### 插入失败时的提示（toast）

| toast 文案 | 含义 |
|---|---|
| 已添加到会话草稿 | 成功 |
| 当前面板不在会话上下文中，无法插入到输入框 | 面板没拿到会话的输入能力，换从会话页打开右侧栏 |
| 输入框草稿已变化，未插入；请避免在插入期间编辑草稿 | 插入期间草稿被改动，会拒绝插入而不是插到错位置，重试即可 |
| 没有可插入的内容 | 目标内容为空 |

## 5. MCP 集成：权限边界与写操作提醒

模型侧工具由**插件自己**桥接（`src/host/mcp-bridge.ts`）：直连本机 Zotero 集成 MCP（地址取自配置字段 `mcpUrl`，默认 `http://127.0.0.1:23120/mcp`），按配置里的 `disabledMcpTools` 过滤后，以 `mcp__zotero__<原始名>` 注册给模型。[cordis.patch.yml](../../cordis.patch.yml) **不再**插入 `@deepseek-ai/dsh-mcp-client` —— 官方 MCP 客户端不支持按工具开关，且同 `serverName` 会与自注册工具重名冲突。

服务端细节见 [Zotero集成MCP服务参考.md](../Zotero文档/Zotero集成MCP服务参考.md)。本机实测暴露 **25 个工具**。

### ⚠️ 权限边界：这些工具里有写操作

写能力有两处，都要单独收：**集成 MCP 的 25 个工具里有 10 个写工具**（下面这张表），以及**插件自有的 5 个标注 / 笔记工具**（只在「Zotero 写权限」打开时才注册）。

| 工具 | 作用 |
|---|---|
| `write_item` | 新建条目（`create`）/ 把本地文件导入为附件（`import`）/ 重挂附件（`reparent`） |
| `write_note` | 新建 / 更新 / 追加笔记 |
| `write_tag` | 加 / 删 / 替换标签 |
| `write_metadata` | 改条目元数据字段与作者 |
| `add_by_identifier` | 按 DOI / arXiv / ISBN / PMID 批量入库（走 Zotero 自带解析器） |
| `create_collection` | 新建分类 |
| `update_collection` | 改名 / 改父分类 |
| `delete_collection` | **删除分类** |
| `add_items_to_collection` | 把条目加进分类 |
| `remove_items_from_collection` | 把条目移出分类 |

也就是说，**模型可以在你不知情的情况下改动文库**。删分类与改归属是不可逆的结构变更（`delete_collection` 尤其在模型理解错分类名时危险）。

### 为什么写操作要优先走 MCP

这些写工具在 Zotero 进程内直接改库，不经过本地 API，**不会触发 Zotero 的「本地 API 授权」弹窗**。

反过来说，如果让模型用 shell/curl 直接打 `127.0.0.1:23119` 的写接口，就必须先 `POST /api/local/authorize` 换 key，而这个端点有两个坑：

1. **每次调用都会弹一次授权框**，它不会按应用名复用已有授权；
2. 用户点「允许」拿到的 key 是**一次性**的，首个写请求就被 Zotero 删除；只有点「始终允许」才是长期 key。

这就是「每写一次就要点一次允许」的根源。为此插件在 [mcp-bridge.ts](../../src/host/mcp-bridge.ts) 里给所有写工具的描述统一注入了「首选写通道」引导语，并把高频场景直接写进提示：

- **导入本地文件挂到某条目下**：`write_item` + `action: "import"` + `filePath` + `parentItemKey`，一次调用完成；
- **按 DOI / arXiv / ISBN / PMID 入库**：`add_by_identifier`，元数据由 Zotero 解析器生成，比手填准。

建议：

- 默认全开可以接受——多数调用是读工具，写工具偶尔很有用（比如「把刚找的文献收进 DRG 分类」）。
- 想收紧成纯只读：把「设置 → Zotero 插件」里「MCP 工具」区的 10 个写工具关掉，**再把「Zotero 写权限」开关关掉**，两边一起才收得住——前者关掉模型改条目/分类的能力，后者同时摘掉模型的 5 个 `zotero_*` 写工具和面板里的全部写入口。
- 涉及 `delete_collection` / `remove_items_from_collection` 的请求，建议先让模型列出目标再确认，不要一句话让它删。

### 标注与笔记的写：插件自带的 `zotero_*` 工具

集成 MCP 没有标注与笔记的写工具（`get_annotations` / `search_annotations` 都只读），这两类改动走本地 API，由插件自己注册 5 个工具：

| 工具 | 作用 |
|---|---|
| `zotero_create_note` | 在某条目下新建笔记（正文是 HTML） |
| `zotero_update_note` | 整篇替换笔记正文；含引文 / 标注锚点的也能改，但要把锚点属性原样带回 |
| `zotero_delete_note` | **硬删**笔记，不进 Zotero 回收站 |
| `zotero_update_annotation` | 改一条高亮 / 划线的颜色、评论、页码标签、标签，或两者互转 |
| `zotero_delete_annotation` | **硬删**一条标注，不进回收站 |

**没有「新建标注」这个工具**，是刻意的：PDF 高亮要写用户空间坐标，那组数只有插件阅读器里的文本层算得准，让模型编坐标只会在库里画出莫名其妙的矩形。要给文字加高亮，请在右侧阅读面板划选后点色块。

这 5 个工具只在「Zotero 写权限」开关打开时注册，关掉即从模型的工具表里消失。它们经本地 API 写库，所以需要一次授权：在「设置 → Zotero 插件」里点「授权 Zotero 写权限」，在 Zotero 弹窗选 **「始终允许」**（选「允许」的 key 用一次就失效）。

**「始终允许」的授权只点一次就够**：Zotero 发的长期 key 会被插件存到本机 `~/.dsh/storages/dsh-plugin-zotero/local-api-key.json`（文件权限 `0600`，只在 Host 进程内读写，不进配置表单、不回显给模型、不经 HTTP 暴露）。之后重启 dsh、重启 Zotero 都直接复用，不会再弹框；升级到带本功能的新版本时，插件还会从 Zotero 自己的密钥库（profile 目录的 `localAPIKeys.json`）里**导入**你此前点过的「始终允许」，升级后同样零点击。要撤销授权，在 Zotero 里清除本地 API 授权即可 —— 下一次写入会收到 401，插件随即删掉本地副本并回到「未授权」。

## 6. 设置入口：设置 → Zotero 插件

入口只有一个：左下角账号旁 **「设置」** → 左侧导航最下面的 **「Zotero 插件」**（与「通用设置 / 模型 / 内置插件 / Agent 预设」并列的独立一页）。左侧导航项由插件自己注册，所以插件装没装、启没启一眼就能看出来；插件没被 Host 加载时这一页整体不出现，不会留一个点不开的空壳。

> 插件页（顶部导航 **「插件」**）里的 `dsh-plugin-zotero` 行不再挂配置入口 —— 那里只负责安装 / 启停 / 查看运行状态。

表单分三组，**「Zotero 写权限」在最上面**——不点那两个按钮，所有写操作都会失败，所以先摆出来。

**Zotero 写权限**（置顶卡片）

- 顶部一行是「允许写入 Zotero」开关（默认关）。
- 下面一行显示当前授权状态：未开启 / 未授权 / 已授权（永久有效，重启复用）/ 一次性授权。
- 再下面**两个按钮**：**「授权 Zotero 写权限」**（主操作，Zotero 会弹一次确认框；已拿到长期授权后降级为描边的「重新授权」）和描边的 **「重新读取」**（重新读一次本机保存的授权状态）。没授权过就先点前者，写入报 `zotero_need_auth` 后仍不生效再点后者。
- 开关还没落盘时授权按钮是禁用的，卡片里会写明「请先打开上面的开关，再授权」——改完停手约半秒就自动保存，按钮随即可用。

**API 设置**

| 字段 | 默认 | 生效点 |
|---|---|---|
| Zotero 地址 | `http://127.0.0.1:23119` | 本地 API 探活与全部请求 |
| 请求超时（毫秒） | `5000` | 单次本地 API 请求超时 |
| 全文上限（字节） | `204800` | 附件全文返回上限（超出截断） |
| 默认条目数 | `50` | 面板条目列表默认拉取条数 |

**MCP 设置**

| 字段 | 默认 | 生效点 |
|---|---|---|
| 集成 MCP 地址 | `http://127.0.0.1:23120/mcp` | 集成 MCP 探活、工具列表与工具调用 |
| MCP 探活超时（毫秒） | `800` | TCP 探活集成 MCP 端口超时 |

MCP 组下方是 **「MCP 工具」** 区：现场列出集成 MCP 的全部工具（`mcp__zotero__<原始名>` + 描述），每行右侧一个开关。关掉某个工具后（改动自动保存），模型侧就不再注册它（等价于把它从模型的工具表里摘掉）；「重新读取」按钮可重新拉一次清单。

自动保存与重置（**这一页没有保存按钮**）：

- 改完停手约 0.6 秒即自动写入 profile 的 patch 层 `~/.dsh/profiles/<profile>/cordis.patch.yml`，**无需重启**即时生效——字段标了 Schemastery `.volatile()`，只提交新值并唤醒引用，条目本身不重挂。关闭设置对话框时若还有没落盘的改动，会立刻冲一次。
- 写盘过程中页面上方会短暂显示「保存中…」，失败则显示红字「保存失败」；失败不会自动重试，再改一次字段即重新尝试（常见原因是该值被更高优先级的 patch 层覆盖）。
- 工具开关同样写进 `disabledMcpTools` 字段（工具原始名数组）；每次落盘后会各同步一次工具注册。
- 字段旁出现「已覆盖」表示该值来自 patch 层而非默认值；点「恢复默认」可清掉覆盖。
- 数字类字段填了非数字（如字母）时不落盘，字段下方有红色提示，改回合法值即自动保存。
- 「设置 → 内置插件」是**只读**清单（只看列表与运行状态），没有编辑入口；本插件的配置只在「设置 → Zotero 插件」这一页。

## 7. 常见错误对照表

| 现象 / 错误码 | 原因 | 处理 |
|---|---|---|
| 状态点「Zotero 未连接」，`zotero_unreachable` | Zotero 没启动，或本地 API 被关，连接被拒 | 启动 Zotero，确认 §2 的选项已勾选 |
| `zotero_disabled` | 本地 API 已开，但「允许本机其他应用与 Zotero 通信」没勾 → 403 | 勾选后点面板「刷新」 |
| `zotero_not_found` | 条目 / 分类 key 已失效（被删或换了文库） | 刷新后重新选 |
| PDF 打不开，提示「附件打不开：附件文件不存在：…」 | Zotero 有附件记录，但磁盘上那份文件不在了：链接文件被移动 / 改名、外接盘没挂载、换机器后只同步了条目没同步附件 | 在 Zotero 里双击该附件确认；把文件放回原路径，或重新挂一份附件 |
| PDF 打不开，提示「附件打不开：附件 xxx 没有本地文件」 | 该附件只有条目记录、没有本地文件（未下载完，或是网页链接型附件） | 在 Zotero 里「查找可用的 PDF」或重新下载该附件 |
| PDF 打不开，提示「没有权限读取附件文件：…」 | 运行 DSH 的账户读不到那个路径（放在别的账户目录 / 系统受保护目录下） | 把 Zotero 数据目录挪到当前账户可读的位置，或调整目录权限 |
| PDF 打不开，提示「Zotero 返回了 404，但附件本身可以读取」 | 瞬时故障：Zotero 刚启动、正在重建索引，或附件在读取期间被移动 | 点「重试」；反复出现就重启 Zotero 再试 |
| PDF 打不开，提示「附件打不开：Zotero 中找不到该资源（404）」 | 该附件 key 在当前文库查不到：条目已被删除，或它属于**群组文库**（v1 只读个人文库 `/api/users/0`） | 刷新后重新选；群组文库的条目暂不支持直接打开 |
| `bad_request` / `internal_error` | 参数非法，或插件内部异常 | 刷新重试；持续出现看 dsh 控制台 |
| 状态点「模型工具不可用」 | 23120 无监听（集成 MCP 服务没装 / 没启用） | 确认服务在跑；面板本身可继续用 |
| 条目详情没有「全文」 | 该条目没有可用附件全文（或附件没做全文索引） | 先给条目添加 PDF 附件，并在 Zotero 里完成全文索引 |
| 条目详情没有引用块 | 顶层条目本身就是**裸 PDF 附件**（直接拖入的文件），没有书目元数据 | 正常现象：本地 API 对裸附件不生成 `csl-entry`。元数据可从附件所属条目取 |
| 整目录引用拿不到 bib | 本地 API 的 `/collections/<key>/items?format=bib` 返回空 body | 插件已绕开：改走 `/items?itemKey=...` 批量取（每批 ≤ 50），属上游限制 |
| 树里没有「最近阅读」/「重复条目」 | Zotero 这两个视图由客户端本地算法实现，本地 API 未暴露（`/recents`、`/items/duplicates` 均 404） | 已知限制，无法在插件里复刻 |
| 划词不出「添加摘录」 | 不是真实的鼠标拖拽选中（脚本建选区不行），或选区跨出了全文块 | 用鼠标在全文块内拖选 |
| `zotero_need_auth` | 写权限开关已开，但本机还没有可用的长期授权（从没授权过，或在 Zotero 里撤销了授权） | 「设置 → Zotero 插件」里点「授权 Zotero 写权限」，弹窗里选 **「始终允许」**；插件会把这次授权存到本机，之后重启不用再点 |
| `zotero_stale`（412） | 这条标注 / 笔记在你编辑期间被 Zotero 那边改过，版本对不上 | 刷新详情拿到新版本再改，插件不会覆盖对方 |
| `zotero_denied` | Zotero 弹窗里点了「拒绝」 | 重新点授权按钮并允许 |
| `zotero_rate_limited`（429） | 一分钟内申请授权超过 5 次 | 等一分钟再点一次；反复弹框说明第一次没选「始终允许」 |
| 划选后不出标注色块 | 「Zotero 写权限」开关没开（色块那一排整体不出现），或选区不在 PDF 文本层上 | 打开开关；在 PDF 页面里用鼠标拖选 |
| 「这段选区定位不到 PDF 里的位置，无法标注」 | 选区落在没有文本层的页（扫描件、纯图片页） | 该页无法按文字标注，可在 Zotero 里用手写 / 截图标注 |
| 笔记编辑框里出现橙色提示 | 这条笔记含 Zotero 引文 / 标注锚点（`data-citation` / `data-annotation`） | 提示不是错误：改文字没事，别删改这些属性，删了 Zotero 侧的引文会失联 |
| 删除点了第一次没删 | 删除要连点两次（「删除」→「确认删除」） | 第二次才真删；硬删不进 Zotero 回收站 |
| 全文显示可能被截断 | 单条全文上限 200 KB | 属刻意限制；需要完整内容让模型用 `mcp__zotero__get_content` |
| 搜索 / 树加载后总是空 | 文库本身为空，或分类下确实没有条目 | 换分类或换关键词确认 |
| 网页条目只显示「没有保存网页快照」 | 抓取时没勾「保存网页快照」，或该站点没有对应 translator | 在浏览器里用 Zotero Connector 重新抓一次并勾上快照；先用「打开原网页」将就 |
| 快照页面缺图 / 排版错乱 | 旧式「HTML + 资源目录」快照，沙箱 CSP 不允许加载同目录外部资源 | 已知限制；在 Zotero 里重新抓取一次会得到自包含的单文件快照 |
| 快照底部提示「有 N 条标注未能定位」 | 页面脚本改写 DOM，选择器与原文文本搜索都对不上 | 该标注仍能在列表里看到与插入；确需定位可在 Zotero 里重新划一次 |
| 快照里点链接跳出插件 | 链接交给系统浏览器打开（沙箱内不允许导航） | 属预期行为，避免把快照页面本身导航走 |
