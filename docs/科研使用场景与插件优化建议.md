# DSH Zotero 插件科研适用性评估

> 评估日期 2026-11-23。基于仓库源码 `b0a2065`（`package.json` 版本为 `1.1.0`）。结论来自源码走查，未在 Zotero 与 DSH 中进行端到端实测。MCP 能力以实际连接的服务及启用的工具为准。

## 目前能支撑哪些科研工作

**当前插件适合已有文献的浏览、单篇辅助精读和带原文的讨论。多篇综述可以起草，但逐项核对仍依赖人工。正式引文和系统综述应继续使用已有的 Zotero 写作及审查流程。** 对科研人员来说，下一步最重要的是能确认模型看了哪个版本、看了哪些内容，并能从回答回到原文证据。

| 科研任务 | 当前支持程度 | 现有能力与限制 |
| --- | --- | --- |
| 在已有文库中找文献、做初筛 | 可用于日常工作 | 面板支持分类、标签和按标题／作者／年份、字段或全文搜索。全文检索依赖 Zotero 索引，扫描件等未建立可用文本索引的资料可能漏检。条目详情能看摘要，但普通条目胶囊主要提供书目信息。 |
| 精读方法与结果、核对图表 | 可用于辅助阅读 | PDF 可按目录跳转、恢复阅读进度、划词摘录和翻译，也可按章节或字符范围提交索引正文。截图以图片附件和出处说明进入草稿，PDF 截图在可取得信息时带页码和最近的章节，图表解读需要支持图像输入的模型。涉及样本量、单位、统计口径和公式时，仍需核对原页及图注。 |
| 管理标注、积累读书笔记 | 可用于个人工作 | 标注可带页码和评论加入对话，笔记可作为纯文本提交。开启对应写权限后，面板可把标注与笔记写回 Zotero。历史胶囊支持查看已发送的引用文本，从可识别的条目类胶囊可打开条目详情。 |
| 比较多篇论文、起草综述 | 部分支持 | 已支持列表多选、分类及标签引用，也有综述矩阵提示词。普通条目多选主要发送书目信息，分类或标签胶囊只发送最多 50 条的清单预览。逐篇依据方法、样本和结果对比，需要额外加入正文或由已启用的 MCP 工具取文。 |
| 将引用用于论文写作 | 部分支持 | 条目详情可显示 APA 参考文献文本，条目胶囊在 Zotero 成功返回书目时也会带上 APA。服务端已有分类书目接口。面板尚缺专用的样式选择、复制和批量导出入口，正文引文仍需在写作端通过 Zotero 插入。 |
| 开展可复核的系统综述 | 仅能辅助阅读与提取 | 模型可通过已启用的 MCP 工具检索已有文献库，并可在获得相应写权限时按 DOI 等标识符入库。当前缺少跨数据库检索记录、去重与筛选决策、排除理由及数据提取复核流程。 |

## 优先优化现有功能

### P0 · 让正文选区与当前附件一致

切换到译文或补充材料时，阅读器和目录会切换到当前附件，但全文选择器使用条目详情中的首份可用索引正文。提交时也按父条目重新读取首份可用正文。因此，用户可能按译文目录选中一节，实际发送的却是另一份附件的文本。原文、译本和补充材料的页码及章节各自独立，这会直接影响结论能否核对。[附件选择](../src/client/ItemDetail.tsx) · [正文范围入口](../src/client/InfoPanel.tsx) · [提交时取文](../src/client/cite.ts) · [附件全文获取](../src/zotero/client.ts)

- 将范围预览和提交绑定至同一附件，显示附件名及索引状态。当前附件无可用索引时，提示改用截图或明确切换到另一份附件。发送时如发现索引已变化并影响选区，提示重新确认范围。
- 保留现有的截断和估算提示，并在发送前显示实际将提交的片段。按章节勾选多个不相邻章节时，当前实现会取首尾之间的连续区间，可能把中间未勾选的章节一起发出。应按实际发送范围预览，定位失败时由用户确认后再扩大范围。[章节范围规划](../src/client/fulltextPlan.ts) · [范围切片](../src/client/fulltextRange.ts)
- **验收**：用原文、译本及未索引的补充 PDF 测试。切换附件后，预览与发送内容一致。勾选不相邻章节时，用户能确认哪些段落将发送。遇到长文截断或无索引时，草稿能明确显示覆盖范围。

### P1 · 从回答回到证据所在位置

截图已有页码信息，标注可带页码，历史胶囊也可打开条目。差距在于划词摘录和译文没有记录附件及页码，历史入口目前只传条目 key。全文中的章节页码有时由书签范围估算，无法作为精确引文位置。[引用展开](../src/client/compose.ts) · [历史回跳](../src/client/historyRef.tsx) · [截图出处](../src/client/viewer/shot/metadata.ts)

- 优先让截图、标注和划词摘录保留附件与原文位置。PDF 区分显示页标签和实际跳转页序，网页快照保留章节或锚点。逐步为全文片段补充真实的页级来源。
- 给送入会话的证据片段分配可引用的编号，让回答中的编号指回已提交的片段。无法定位或只有估算时，明确显示精度，并保留可打开的条目或附件。
- **验收**：同一条目含原文与译本，且 PDF 印刷页码与文件页序不一致时，从回答中的证据编号仍可打开正确附件和页面。选区可定位时恢复选区，定位失效时显示可用的回退位置。

## 建议补充的功能

| 优先级 | 建议 | 最小交付与验收 |
| --- | --- | --- |
| P1 | **批量准备正文，生成可核对的综述矩阵** | 复用已有多选和对比模板。发送前逐篇列出附件、已选范围、预计用量及状态，例如仅书目、已取正文、索引缺失、正文截断。首版支持按用户选择的范围取文，并输出带证据编号的对比表，先覆盖研究设计、样本／数据、主要结果和局限。用混有长文、无索引 PDF 和仅有书目的文献组验收，表格能区分「本次未覆盖」与「已核对原文，作者未报告」。 |
| P2 | **从 Zotero 直接复制格式化参考文献** | 在条目和多选入口复用 Zotero 的 CSL 输出，首版提供 APA 和 GB/T 7714。批量复制应显示实际输出条数及未输出项，并核对整组排序与数字编号，避免直接拼接分批渲染结果。用中英文期刊论文、预印本和会议论文对照 Zotero 输出验收。BibTeX／RIS 可随明确的导出需求补充，Word 正文引文与参考文献联动继续交给 Zotero 写作插件。 |
| 按需求评估 | **缺少索引时的文本提取，以及批量提取表导出** | 扫描文献使用频繁时，优先提供重新索引或 OCR 入口，并保留页码与提取状态。综述团队有复核需求时，再把已确认的矩阵导出为 CSV，保留文献标识、提取字段及证据位置。 |

外部数据库检索和引文追踪适合在阅读与证据定位稳定后，按具体学科和检索需求评估。若将系统综述纳入产品范围，应把可保存的检索式、检索日期、筛选决定及排除理由作为独立工作流设计。文库同步、去重和协作可继续沿用 Zotero。

涉及未发表手稿或受限资料时，发送前应能确认会话将使用的模型及提交内容。也应让划词翻译的服务选择可见。当前选择 DeepSeek 翻译时，调用失败可能回退到 Bing，可补充禁用自动回退的选项。[翻译实现](../src/host/translate.ts)
