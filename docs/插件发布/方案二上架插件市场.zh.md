# 方案二：上架插件市场（操作手册）

> 适用：把插件收录进 [awesome-dsh-plugin](https://github.com/awesome-dsh-plugin/awesome-dsh-plugin)，让用户从市场一键安装。
>
> 原理：市场没有投稿接口。上架 = 提一个 `data/plugins/<owner>__<repo>.yml` PR；维护者合并后，上游 nightly 生成 `plugins.json` / `index.json`，市场读取。**npm 映射由 bot 自动探测，条目里不能手写。**
>
> 本流程已按 2026-10-20 的 nightly 实测走通（v0.1.2：`npm` / `version` / `stars` / `install` 全部生效）。

## 前置条件

| 项 | 要求 |
|---|---|
| 仓库 | 公开、创建满 1 天、有真实代码、有 `dsh-plugin` topic |
| manifest | `package.json` 必须声明 `dsh.bundle.patch`；只有 `dsh.client` 不算可安装 |
| 账号 | npm 邮箱已验证；可登录 npm；有 GitHub fork/PR 权限；本机有 `pnpm` |
| 版本 | `engines.dsh` 与当前 dsh 运行时匹配 |

工具分工：**构建/打包/发布用 `pnpm`；包分发到 npm registry；用户安装用 `dsh plugin add`（内部也是 pnpm）**。不要用 `npm publish`：本项目 v0.1.0 用 npm CLI 首发布时进了 staged publishing，出现 `0.0.0-stage` 占位版本。

## 第 1 步：补齐 package.json

```json
{
  "name": "dsh-plugin-zotero",
  "version": "0.1.2",
  "description": "一句话英文说明",
  "keywords": ["dsh", "dsh-plugin", "zotero"],
  "license": "MIT",
  "repository": { "type": "git", "url": "git+https://github.com/peijiping/dsh-plugin-zotero.git" },
  "homepage": "https://github.com/peijiping/dsh-plugin-zotero#readme",
  "type": "module",
  "main": "lib/index.js",
  "types": "./lib/index.d.ts",
  "exports": {
    ".": { "types": "./lib/index.d.ts", "default": "./lib/index.js" },
    "./client": "./client/client.js"
  },
  "files": ["lib", "client", "cordis.patch.yml"],
  "engines": { "dsh": ">=0.2.0-rc.2 <0.3.0-0" },
  "peerDependencies": {
    "@deepseek-ai/cordis": "^4.0.1",
    "@deepseek-ai/schemastery": "^3.18.4"
  },
  "dsh": {
    "bundle": { "patch": "./cordis.patch.yml" },
    "client": { "platform": "web", "inject": ["..."] }
  },
  "scripts": {
    "build": "tsc -p tsconfig.json",
    "build:client": "tsdown",
    "prepack": "pnpm build && pnpm build:client"
  }
}
```

说明：

- `dsh.bundle.patch`：收录硬条件，指向仓库根的 `cordis.patch.yml`。
- `prepack`：`pnpm pack` / `pnpm publish` 前自动构建；没有它产物缺 `lib/`。
- `repository`：npm probe 用它确认包与仓库归属，必须回指本仓库。
- `engines.dsh`：官方「发现」页兼容性 + 安装前的版本闸门。
- `peerDependencies`：要与宿主共享实例的 dsh 包（同时放进 devDependencies）。
- `files`：只列真实存在的产物目录。
- `types` / `exports`：让 TS 与 client 入口都可解析。

## 第 2 步：忽略打包产物

`.gitignore` 增加一行：

```
/*.tgz
```

## 第 3 步：仓库加 topic

网页：仓库首页 About → Topics → 加 `dsh-plugin`（顺带 `zotero`、`dsh`）。

API（**覆盖式替换**，要一次列全）：

```sh
TOKEN=$(printf 'protocol=https\nhost=github.com\n\n' | git credential fill | sed -n 's/^password=//p')

curl -s -X PUT \
  -H "Authorization: Bearer $TOKEN" -H 'Accept: application/vnd.github+json' \
  -H 'Content-Type: application/json' \
  https://api.github.com/repos/peijiping/dsh-plugin-zotero/topics \
  -d '{"names":["dsh-plugin","zotero","dsh"]}'
```

`TOKEN` 从 macOS 钥匙串取，后续所有命令复用；不要打印。

## 第 4 步：构建、打包、自测

```sh
cd /Users/peijiping/Documents/Codes/TS/dsh-plugin-zotero
V=0.1.2                # 改成当前版本号

pnpm typecheck:client  # 可选
pnpm pack              # 触发 prepack，产出 dsh-plugin-zotero-$V.tgz
tar -tzf dsh-plugin-zotero-$V.tgz | sort
```

产物必须包含：

```
package/package.json
package/cordis.patch.yml
package/lib/index.js
package/lib/index.d.ts
package/client/client.js
package/README.md
package/LICENSE
```

真实加载测试（会 import 模块，能抓出 `MODULE_NOT_FOUND`）：

```sh
DSH_HOME=/tmp/dsh-pack-test dsh plugin --profile test add ./dsh-plugin-zotero-$V.tgz
DSH_HOME=/tmp/dsh-pack-test dsh --profile test --dump-config-schema | grep -c dsh-plugin-zotero
```

> 计数 ≥1 即加载成功。用 `web` profile 时 dsh 自身的诊断可能让退出码非 0，以输出里是否出现插件名为准。

## 第 5 步：发布到 npm

```sh
V=0.1.2                # 与 package.json 的 version 一致
git add -A && git commit -m "发布 v$V" && git push
pnpm publish --access public
```

说明：

- 2FA：在交互终端输入 OTP；或使用 bypass 2FA 的 granular token。恢复码不能用于 `--otp`。
- 报 `ERR_PNPM_OTP_NON_INTERACTIVE`：改到终端执行。
- 发布后核对 registry（不要只看“发布成功”）：

```sh
curl -s https://registry.npmjs.org/dsh-plugin-zotero | python3 -c "
import json,sys
d=json.load(sys.stdin)
print('latest', d['dist-tags']['latest'])
print('versions', list(d['versions']))
print('published', d['time'][d['dist-tags']['latest']])
"
```

- 只看到 `0.0.0-stage`：staged publishing。npm 网页 → Staged Packages → Approve，或 `pnpm stage approve <stage-id>`（pnpm ≥ 11.3）。
- 发布后几分钟内 tarball 可能 404（CDN 缓存 5 分钟），等 5 分钟再安装。
- 急着重装可加 cache-buster 验证：`curl -sL "...tgz?cb=$(date +%s)" -o x.tgz`。

## 第 6 步（可选）：发 GitHub Release

npm 是主路径，Release 只做兜底（npm 映射生效前，或 registry 不可达）。资产名固定为 `dsh-plugin-zotero.tgz`，这样 `releases/latest/download/` 永久链接不随版本失效。

```sh
V=0.1.2

# 建 release（不要传 target_commitish，短 SHA 会 422）
curl -s -X POST \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  https://api.github.com/repos/peijiping/dsh-plugin-zotero/releases \
  -d "{\"tag_name\":\"v$V\",\"name\":\"v$V\",\"body\":\"发布说明\",\"draft\":false,\"prerelease\":false}"

# 取 release id
RID=$(curl -s -H "Authorization: Bearer $TOKEN" \
  https://api.github.com/repos/peijiping/dsh-plugin-zotero/releases/tags/v$V \
  | python3 -c "import json,sys;print(json.load(sys.stdin)['id'])")

# 上传资产（uploads.github.com）
curl -s -X POST \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/gzip' \
  --data-binary @dsh-plugin-zotero-$V.tgz \
  "https://uploads.github.com/repos/peijiping/dsh-plugin-zotero/releases/$RID/assets?name=dsh-plugin-zotero.tgz"
```

网页端：Draft a new release → 选新 tag → 上传 tgz → 把资产重命名为 `dsh-plugin-zotero.tgz` → Publish。

可选：想在市场卡片显示截图，在仓库根放 `screenshots.json`（引用 1~8 张 GitHub 托管图片），下次构建生效。

## 第 7 步：提交收录 PR

只加一个文件：`data/plugins/peijiping__dsh-plugin-zotero.yml`。

```yaml
url: https://github.com/peijiping/dsh-plugin-zotero
name: peijiping/dsh-plugin-zotero
category: tools
tarball: https://github.com/peijiping/dsh-plugin-zotero/releases/latest/download/dsh-plugin-zotero.tgz
description:
  en: '一句话英文描述，以句号结尾。'
  zh: 一句话中文描述，以句号结尾。
```

字段规则：

| 字段 | 要求 |
|---|---|
| `url` | 仓库地址，完全一致，不要多余斜杠 |
| `name` | `owner/repo` |
| `category` | 取自上游分类表（`tools` / `ui` / `dev` / `theme` 等） |
| `tarball` | 可选；必须是 GitHub Release 托管的 https `.tgz` |
| `description.en` | 必填，单行、句号结尾、不夸张；含 `: ` 时必须加引号；描述会与代码核对 |
| `description.zh` | 可选，维护者会补 |
| `npm` / `version` | **禁止手写**；未知字段会被 CI 拒绝 |

> 两个 README 是生成物，不要手工编辑。

命令流程（fork → 分支 → 提交文件 → 开 PR）：

```sh
UP=awesome-dsh-plugin/awesome-dsh-plugin
FILE=data/plugins/peijiping__dsh-plugin-zotero.yml
BR=add-dsh-plugin-zotero

# fork（已 fork 过会返回已存在，可忽略）
curl -s -X POST -H "Authorization: Bearer $TOKEN" https://api.github.com/repos/$UP/forks

# 从 fork 的 main 建工作分支
SHA=$(curl -s -H "Authorization: Bearer $TOKEN" \
  https://api.github.com/repos/peijiping/awesome-dsh-plugin/git/ref/heads/main \
  | python3 -c "import json,sys;print(json.load(sys.stdin)['object']['sha'])")
curl -s -X POST -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  https://api.github.com/repos/peijiping/awesome-dsh-plugin/git/refs \
  -d "{\"ref\":\"refs/heads/$BR\",\"sha\":\"$SHA\"}"

# 提交条目（先把上面的 YAML 存成 entry.yml；content 必须是 base64）
CONTENT=$(base64 -i entry.yml | tr -d '\n')
curl -s -X PUT -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  "https://api.github.com/repos/peijiping/awesome-dsh-plugin/contents/$FILE" \
  -d "{\"message\":\"Add peijiping/dsh-plugin-zotero\",\"branch\":\"$BR\",\"content\":\"$CONTENT\"}"

# 开 PR
curl -s -X POST -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  https://api.github.com/repos/$UP/pulls \
  -d "{\"title\":\"Add peijiping/dsh-plugin-zotero\",\"head\":\"peijiping:$BR\",\"base\":\"main\",\"body\":\"PR 说明\"}"
```

网页端等价做法：fork → Add file → 提 PR 到上游 `main`。

## 第 8 步：检查 PR 与收录（L1–L5）

```sh
TOKEN=$(printf 'protocol=https\nhost=github.com\n\n' | git credential fill | sed -n 's/^password=//p')
UP=awesome-dsh-plugin/awesome-dsh-plugin
PR=7644                # 换成实际 PR 编号
FILE=data/plugins/peijiping__dsh-plugin-zotero.yml
```

### L1 PR 状态

```sh
curl -s -H "Authorization: Bearer $TOKEN" https://api.github.com/repos/$UP/pulls/$PR \
  | python3 -c "import json,sys;d=json.load(sys.stdin);print('state',d['state'],'| merged',bool(d['merged_at']),'| mergeable',d['mergeable'])"
```

`merged True` → 去 L3；`open + mergeable True` → 看 L2；`mergeable None` → 等 GitHub 计算。

### L2 CI 两项

`check` 校验表单（YAML 合法、只加一个文件、路径规范）；`Submission gate` 校验语义（`dsh.bundle` 存在、仓库满 1 天）。

```sh
SHA=$(curl -s -H "Authorization: Bearer $TOKEN" https://api.github.com/repos/$UP/pulls/$PR \
  | python3 -c "import json,sys;print(json.load(sys.stdin)['head']['sha'])")

curl -s -H "Authorization: Bearer $TOKEN" \
  "https://api.github.com/repos/$UP/commits/$SHA/check-runs" \
  | python3 -c "import json,sys;[print(c['name'],'|',c['status'],'|',c['conclusion']) for c in json.load(sys.stdin)['check_runs']]"
```

| 结论 | 处理 |
|---|---|
| `check: success` + `Submission gate: success` | 等维护者合并 |
| `Submission gate: neutral` | 机器人限流未核验；维护者只合 success → 推空提交重触发 |
| `Submission gate: failure` | 按 summary 修条目或仓库 |
| `Repository config guard: failure` | 不阻塞，可忽略 |

`neutral` 重触发（空提交）：

```sh
HEAD=$(curl -s -H "Authorization: Bearer $TOKEN" \
  https://api.github.com/repos/peijiping/awesome-dsh-plugin/git/ref/heads/add-dsh-plugin-zotero \
  | python3 -c "import json,sys;print(json.load(sys.stdin)['object']['sha'])")
TREE=$(curl -s -H "Authorization: Bearer $TOKEN" \
  https://api.github.com/repos/peijiping/awesome-dsh-plugin/git/commits/$HEAD \
  | python3 -c "import json,sys;print(json.load(sys.stdin)['tree']['sha'])")
NEW=$(curl -s -X POST -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  https://api.github.com/repos/peijiping/awesome-dsh-plugin/git/commits \
  -d "{\"message\":\"chore: re-trigger CI\",\"tree\":\"$TREE\",\"parents\":[\"$HEAD\"]}" \
  | python3 -c "import json,sys;print(json.load(sys.stdin)['sha'])")
curl -s -X PATCH -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  https://api.github.com/repos/peijiping/awesome-dsh-plugin/git/refs/heads/add-dsh-plugin-zotero \
  -d "{\"sha\":\"$NEW\"}"
```

### L3 条目是否已合并

```sh
curl -s -o /dev/null -w 'HTTP %{http_code}\n' -H "Authorization: Bearer $TOKEN" \
  https://api.github.com/repos/$UP/contents/$FILE
```

`200` = 已合并；`404` = 还没合并。

### L4 / L5 市场数据是否生效

以 npm 上的 catalog 为准（站点 `plugins.json` 本机可能超时或被截断）：

```sh
cd /tmp
curl -s https://registry.npmjs.org/dsh-plugin-catalog/latest \
  | python3 -c 'import json,sys;print(json.load(sys.stdin)["dist"]["tarball"])' \
  | xargs curl -sL -o catalog.tgz
tar -xzOf catalog.tgz package/plugins.json > plugins.json
tar -xzOf catalog.tgz package/index.json > index.json

python3 - <<'EOF'
import json
d=json.load(open('/tmp/plugins.json'))
h=[p for p in d['plugins'] if p.get('url')=='https://github.com/peijiping/dsh-plugin-zotero']
print('plugins.json hits', len(h))
for x in h: print({k:x.get(k) for k in ('npm','version','install','tarball','stars')})
i=json.load(open('/tmp/index.json'))
h2=[p for p in i['plugins'] if p.get('repository',{}).get('url','').endswith('dsh-plugin-zotero')]
print('index.json hits', len(h2))
for x in h2: print(x['versions'])
EOF
```

判据：

- `plugins.json`：`npm` / `version` 非 null；`install` 为 `dsh plugin --profile web add dsh-plugin-zotero`；`stars` 等于 GitHub 星数。
- `index.json`：条目带 `version` 与 `publishTimestamp`。
- catalog 包的版本号/发布时间才代表新鲜度，`plugins.json` 顶层的 `updated` 不是构建时间。
- 站点入口（旧版市场 / dshmarket）：`https://awesome-dsh-plugin.com/plugins.json`。
- 官方「发现」页需手动加索引源：`https://awesome-dsh-plugin.com/index.json`（或 `https://cdn.jsdelivr.net/npm/dsh-plugin-catalog/index.json`）。

## 第 9 步：等 nightly 生效

- cron `23 2 * * *` UTC = **北京时间 10:23**；整轮约 1.5 小时（实测 02:38Z 启动，04:05Z 完成，catalog 04:06Z 发布）。
- 作者**不能**手动 dispatch（`403 Must have admin rights`），只能等。
- 发版时间决定可见时间：赶在 nightly 之前发 npm → 当天可见；晚于 → 次日。
- 生效后 `install` 自动从 tarball 切到 npm，`index.json` 收录，市场卡片显示版本号与星数。
- 卡片不更新：刷新/重开市场；dshmarket 中国区读腾讯镜像（`mirrors.cloud.tencent.com/npm/dsh-plugin-catalog`），可临时切「全球」，或等镜像同步（实测约 1 小时）。

## 第 10 步：以后发新版

1. 改 `version` 并提交。
2. `pnpm publish --access public`（prepack 自动构建）。
3. 可选：建新 Release，资产名仍用 `dsh-plugin-zotero.tgz`。
4. 等 nightly 自动更新 `npm` / `version` / `stars` / `publishedAt` / `enginesDsh`。
5. **不需要重新提 PR**；只有改描述/分类、或仓库改名/迁移时才需要。

## 常见问题

| 现象 | 原因 / 处理 |
|---|---|
| registry 只有 `0.0.0-stage` | staged publishing；批准或改用 `pnpm publish` |
| `ERR_PNPM_OTP_NON_INTERACTIVE` | 非交互终端；到终端执行或建 bypass 2FA token |
| 发布后立刻安装 404 | registry CDN 缓存 5 分钟；等一会儿 |
| 条目写了 `npm:` 被 CI 拒 | 删除；npm 映射只能由 probe 生成 |
| 市场卡片没有版本号 / ★ 为 0 | catalog 未重建或镜像滞后；查 L4、刷市场、切区域 |
| 官方「发现」搜不到 | `index.json` 未收录；需 npm 映射 + 精确版本 + 发布时间 |
| Release API 422 | 不要传 `target_commitish` |
| `raw.githubusercontent.com` 不通 | 改用 `api.github.com` contents 接口 |
| `Submission gate: neutral` | 机器人限流；推空提交重触发 |

## 附：数据与优先级速查

- **安装命令优先级**：npm 已映射 → `dsh plugin --profile web add <包名>`；否则 `tarball`；否则 `github:owner/repo`。
- **npm probe 采纳条件**：仓库 `HEAD/package.json` 的 `name` = npm 包名；npm `latest` 版本的 `repository` 回指同一仓库（大小写不敏感）。
- **`plugins.json`**：旧版市场 / dshmarket 读取，含 `npm` / `version` / `install` / `stars`。
- **`index.json`**：dsh ≥ 0.2.1 官方「发现」读取（format 1），需要 npm 包名 + 精确版本 + 发布时间。
- **tarball 与 npm 都是预构建产物**，用户无需 `allowBuilds`；只有 `github:` 源码安装才需要。
- 分类完整取值见[贡献指南](https://github.com/awesome-dsh-plugin/awesome-dsh-plugin/blob/main/contributing.md)。
